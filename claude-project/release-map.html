Inspecta · one codebase, two apps

Where everything goes

There's only one set of code. EnFact and Site Inspections are both built from it, so a fix made once reaches both apps. The tags EnFact, Contractor and Both only say who a change affects. You don't have to copy anything between the two apps.

I want to…

Try a change on my own phone

Tell Claude: "Put this on my test phone (EnFact / Site Inspections / both)."
  1. Claude pushes the change to test.
  2. GitHub → Actions → Build Android APK → Run workflow. Choose branch test and the App, then Run.
  3. The Test app updates on your phone from Play.

Release to EnFact coworkers

Tell Claude: "Release EnFact." Claude bumps the build number, writes the changelog line, merges test into main and gives you the What's new text.
  1. The EnFact iPhone build starts by itself.
  2. GitHub → Actions → Build Android APK → Run workflow. Choose branch main and App EnFact, tick Publish to Play, paste What's new, then Run.

Release Site Inspections

Tell Claude: "Release Site Inspections." Claude does the same steps for the Site Inspections build number.
  1. GitHub → Actions → Build Android APK → Run workflow. Choose branch main and App Contractor, tick Publish to Play, paste What's new, then Run.
  2. Codemagic → Start new build → Inspecta - Site Inspections (iOS) on main.
  3. Merging to main also starts an EnFact iPhone build. That's harmless, so let it run.

Three rules

  1. Every Claude session works on test. If a session says it pushed somewhere else, ask why.
  2. main only changes when you say "release". Merging always takes everything on test, so release when test is in a state you're happy with.
  3. You don't have to sync the two apps. A report or layout fix reaches both. Only branding differs: EnFact's logo, or the contractor's own.
